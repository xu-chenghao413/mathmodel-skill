# CUMCM clean-room 写作支架

本文件只提供维护者独立撰写的结构提示，不是论文原句库，也不应与任何具体获奖论文逐句对照改写。每个占位符都必须由真实题面、运行结果和核验记录填充。

## 摘要

```text
针对【对象/任务】，本文将【问题拆解】为【子问题或决策链】。
对问题一，建立【模型名/数学对象】，得到【关键数值、单位或区间】，并通过【验证方式】检查【结论边界】。
对问题二，基于【上一问输出或新增数据】构造【模型/算法】，结果表明【关键结果】。
对问题三，采用【模型/场景/优化方法】，在【约束或情景】下给出【决策结论】。
最后，以【灵敏度、外样本、边界或替代模型】评估稳健性，并说明【适用范围与局限】。
```

## 建模段

```text
题目要求回答的是【可观测目标】，而不是泛化的【相近概念】。
在【数据粒度/单位/时间轴】下，定义【变量】并作出【可核验假设】。
因此将【业务关系】表示为【方程、目标函数或约束】。
求解时采用【算法/求解器】，参数为【参数来源】，随机过程使用【seed 或重复策略】。
```

## 结果段

```text
在【数据/情景/参数】下，模型给出【结果】；其与【基线/边界/替代模型】相比【差异】。
该结果支持【回到题目原问的结论】，但不支持【超出证据的强断言】。
```

## 局限与推广

```text
该结论依赖【关键假设/数据范围/算法条件】。
当【压力情景或边界条件】变化时，结果可能出现【方向或失效模式】。
后续可通过【新增数据、替代模型或实验设计】检验，而不是预先承诺固定提升幅度。
```

## 使用检查

- 每个句子都能指向题面、代码、结果表或验证记录。
- 不写“首次、完全、显著优于”等无法由证据支持的词。
- 模型名称、数学定义、实现、求解日志和论文结论保持一致。
- 先填真实结果，再做语言润色；不把本支架当作可直接提交的正文。
