# 已有论文的最小修订合同

用于用户提供现成论文并要求审计、纠错或按意见修改。它不是从零写作流程；用户明确要求重写时才重新设计结构。

## 改前锁定

1. 指定唯一基线，记录 PDF/TeX/图件/代码哈希。保留原文件，在新版本或副本工作。
2. 实测摘要、正文（含参考文献与 AI 声明）、附录页界；不要复制陈旧 QA 数字。CUMCM 可执行当前用户和 skill 明确标注的正文 26–28 页维护者策略。
3. 记录章节顺序、全部图表 label、正文与附录各自数量、图件路径与插入尺寸、附录代码清单。多面板只算一幅图。
4. 建立“问题—证据—最小改动—验证—剩余风险”清单。审计发现与用户偏好分开，未证实的诊断不当作事实。

## 修改边界

- 保留未受影响的章节、文字、公式、图表、数据、代码和参考文献。不因使用可选外部 skill 改成期刊体例。
- 优先原位替换错误句、公式、表格单元和图中文字；只重跑受影响分析，不为改一项统计重绘整套图。
- 不擅自删图、合图、迁表、缩图、改页边距字号，或截断附录来满足自己另定的页数目标。
- 修正结论不代表更换主模型。若核心算法确需替换，先说明具体证据与影响范围并取得方向；不将未完成的替代实验包装成新终稿。
- 数值不一致时先核验假设、单位、数据与实现，不能以一个 FFT、另一篇论文或更低 RMSE 直接宣布原值错误。
- 撤回无可追溯实现的显著性结论；保留真实描述性结果，并明确这不等于完成了新的显著性检验。

## 改后验收

1. 输出局部 diff，逐项对应问题；无任务依据的改动撤回。
2. 章节顺序及全部图表编号/数量不变，原插入尺寸不变；任何确需变化须单列理由与用户授权。
3. 同步实际编译源，完整编译，核对新 PDF 页数三账与适用硬门。
4. 对改动页逐页放大检查，并看全篇缩略图；核对交叉引用、目录/附录、图表裁切与可读性。
5. 旧评分不自动继承。未做完整复审时不新给“修后高分”，未解决的科学问题与已完成的版式修复分别报告。

## 公开仓库边界

本合同只保存通用的最小修订方法，不保存任何用户稿件、真实赛题的评审分数、页数、图表清单、数值答案或团队争议记录。具体项目应在用户自己的工作区维护，并在公开提交前从仓库和 Git 历史中排除。
