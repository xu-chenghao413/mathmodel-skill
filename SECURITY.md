# Security policy

## Scope and supported versions

The latest tagged release and the previous minor release receive security
triage. The repository does not process contest submissions or store user
credentials; most reports concern path handling, archive/install boundaries,
dependency supply chain or accidental disclosure in generated artifacts.

## Reporting

Do not publish vulnerabilities that expose private contest data, credentials or
unpublished manuscripts in a public issue. Use GitHub Security Advisories when
available, or contact the repository owner privately through the contact method
listed on the GitHub profile. Include the affected version, impact, operating
system/client, minimal reproduction and whether the issue is already public.

For ordinary bugs, open an issue with a minimal synthetic reproduction. Remove
team names, school names, contest identifiers, tokens, local paths and source
documents before posting.

The maintainer will acknowledge a report within 7 days and will coordinate a
fix, release note and credit with the reporter when disclosure is appropriate.
Do not upload exploit payloads, secrets or unlicensed source material.
